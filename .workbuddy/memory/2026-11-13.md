- 第二轮 6 题：正文布局形态 / 补列表请求 / 趋势色板 / JSONB 渲染器 / 拆分粒度与前缀 / 同门类出口。
- 用户两次「都是 A」，共 13 项，无异议后开工。

## ★ 调研推翻的两个预设（DB 实测）
1. **`t_industry_detail` 的 8 个 JSONB 90/90 全是 `{}`**，`short_description` / `detailed_description` 也 90/90 为空，`talent_gap` 同样全空。详情接口真正有值的只有主表 9 个概览指标（市场规模 / 年增长率 / 投资热度 / 四大趋势）。旧详情页那 8 个「深度数据」Tab 点开全空白 → 决定「以真实指标为主体 + 空 Tab 不摆」。
2. **后端 `IndustryDetailVO` 不含 `id` / `category` / `description`**（前端 `types/industry/index.ts` 里 `category?: string` 是永远拿不到的幽灵字段）。行业简介长文本 `description` 90/90 有值，但只在 `IndustryListVO`。→ 并发补一次 `GET /industry/list?ids=<id>` 拿 `description` + `category`，失败静默降级。
3. 其它：`/industry/{id}/detail` 仅 `@RequireLogin`；`/industry/enterprises` 是 `@RequireVip` 且 `t_enterprise_industry` **0 行**（VIP 也返回空）；`IndustryListVO.id`（Long）缺 `@JsonSerialize`，但前端 `request.ts` 已用 `json-bigint(storeAsString)` 兜住，本平台不丢精度。

## ★ 经验

## ★ 后端事实（PG 实测，2999 岗位 / 1612 企业）
- `t_enterprise_position` **2999 条**，`position_status` **全是「招聘中」**（常量，不做值→色映射）。
- `recruitment_type` **3 值**：校招 1612 / 社招 1115 / 实习 272（封闭集）。
- `education_requirement` **3 值**：本科 2304 / 硕士 577 / 大专 118（封闭集）。
- `work_experience` **4 值**：应届毕业生 1612 / 3-5年 930 / 在校生 272 / 5年以上 185（封闭集）。
- `salary_min/max` **0 条 NULL**，范围 2~23 / 4~40，**单位是 K**（前端按 k/月 拼是对的）。
- ★ **`deadline` 2999 条全 NULL**、**`apply_link` 2999 条全空** → 截止日期与「去申请」是死字段，本轮不展示。
- `position_tags` 是 PG 数组（`{五险一金,校招,弹性工作}`），后端 `List<String>` → 前端 `string[]` **类型一致**。
- `position_requirement` 是 **93~140 字的编号多行文本**（"1.本科及以上…\n2.熟练掌握…"）→ 按行拆有序列表。
- 每企业岗位数 1/2/3 个（497/843/272 家）；**761 家企业（32%）完全没有岗位** → 空态是常态。
- 接口：`GET /{id}/positions` 是 **@RequireLogin**；`GET /{id}` 免登录；`GET /industries` 是 **@RequireVip**（只放行旗舰版 VIP，普通会员+Pro 都被拒，返回 **200 + 业务码 1005**，不是 HTTP 403）。

## ★ 修掉的 3 个现存 bug
1. **关联行业鉴权判断是死代码**：旧写法 `e?.response?.status === 403` 永远不成立 —— shared `request.ts` 响应拦截器统一 `reject(new Error(message))`（**无 `.response` 属性**，request.ts:211），且 @RequireVip 失败返回 200+码1005。→ 改用 `userStore.userInfo?.memberType === MemberType.VIP` 判定，非 VIP 直接跳过请求。
2. **9 处 Emoji**（📍💰🎓📚⏱📅📋🏭ℹ️🔒）→ 全换 lucide 线性图标。
3. 整页 Tailwind + motion-v → position.css + scoped 组件。

## 实现要点
- `views/enterprise/position/`：`utils.ts` + `position.css`（`.page-enterprise-position`）+ `components/` 5 个组件。
  ★ **类名前缀用 `pos-`** —— `ep-` 已被其它模块占用（实测撞车）。
- Hero 复用列表页同一 `HERO_BG_URL`；企业图标复用列表页 `getEnterpriseIcon`（关键词→性质兜底），两页视觉一致。
- ★ **跨页复用工具栏的样式坑**：`EnterpriseToolsCard.vue` 里的 `hf-card`/`hf-section-title`/`hf-tag` 定义在各**页面级 CSS** 且带页面根类限定（`.page-enterprise-list`）→ 在岗位页（根类 `.page-enterprise-position`）**打不到，工具栏会掉样式**。解法：岗位页 `position.css` 里自带一份同定义的 `.page-enterprise-position .hf-*`（与列表页逐字一致）。两页 hf- 类各自限定、互不干扰（已在产物 CSS 核对）。
- 地点拼接：`work_location` 通常是「省份+城市」完整写法（山西省太原市）→ **优先用 work_location**，缺失才退回 province+city，避免出现「山西 · 太原 · 山西省太原市」。
- Hero 元数据只放「城市·规模」，主营业务较长留给右栏企业信息块，避免同一信息两处重复。
- 薪资用 `#C2410C`（白底 5.18:1 达 AA），不用品牌橙 `#F97316`（2.80:1 不达标）。
