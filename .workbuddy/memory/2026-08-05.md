## 修复 3：高考档案回显时科目被清空（关键 bug）
- 文件：`apps/user/src/views/gaokao/Archive.vue`
- 现象：每次进入「填写/修改档案」，首选科目、再选科目、各科分数全空要重填（基础信息正常）——数据其实在库（后端 GaokaoArchiveServiceImpl 保存/读取字段齐全）。
- **根因**：`loadArchive()` Object.assign 回显 province/year 后，watch(省份/年份) 异步 `getReformModel` 返回时执行 `form.subjectType=''` + 清空 secondSubjects/firstSubjects + 清空所有选考科目分数 → 科目相关数据每次都被清。
- 修复：watch 职责拆分——只加载 reformModel；新增 `restoringData` 标志（loadArchive 里 Object.assign 前置位），watch 内区分「回显」（restoreSubjects 按改革模式回填）vs「用户手动改省份/年份」（resetSubjects 清空）。catch 时清 restoringData 防残留。
- 顺带修：原回填逻辑按 `subjectType==='物理'/'历史'` 判断，3+3 模式会误走 3+1+2 分支——改为按 `reformModel.value?.reformModel` 精确区分（传统文理/3+1+2/3+3/兜底）。

## 修复 4：跨页「直通院校」滚动偏移（第二次修复）
- 现象：跳转后 #exams 区块"0.5 秒后才显现但没滚到位"。
- 根因：onMounted 时机太早——`fetchChannels()` 完成前卡片区是 200px 高 loading 遮罩，此时滚动位置按矮布局计算；0.5s 后卡片渲染把页面撑高，#exams 被往下推 → 视口停在"差一截"处。
- 修复：gaokao/index.vue 改为 `onMounted → initPage()`，`await Promise.allSettled([fetchChannels(), fetchArchive()])` **布局稳定后**再 `scrollToHash('exams')`。教训：**带锚点跳转的页面，滚动必须等数据渲染完（布局稳定）再执行**，否则页面高度变化会把目标区块推走。

## 修复 5：跨页「直通院校」还是滚不到底部（第三次，真正根因）
- 现象：同页点击正常，跨页只跳不滚（到不了底部）。
- **真正根因**：`initPage` 里 `await Promise.allSettled(...)` 只等请求返回，但 `fetchChannels` 把 `loading=false` 后 **Vue 还没把展开的卡片刷进 DOM**（DOM 异步刷新）。此时立刻 `scrollToHash('exams')` 按 200px loading 占位的矮布局算位置 → 滚到半路；卡片撑开后 #exams 被推到页底，滚动已执行完。
- 修复：`initPage` 在 `Promise.allSettled` 之后加 `await nextTick(); await nextTick();` 等 Vue 把卡片刷进 DOM、页面高度稳定，再 `scrollToHash`。同时将 `route.hash === '#exams'` 放宽成 `route.hash.includes('exams')`。
- `navAnchor.ts` 的 `pushNavItem` 跨页分支**去掉**跳转后立刻 `scrollToHash`（不再抢在 loading 占位期滚动造成抖动），统一交给目标页面在数据+DOM 就绪后滚动。同页点击仍直接滚。
- 教训：**等数据返回 ≠ 等 DOM 更新**，量高度/滚动前务必 `await nextTick()` 让 Vue 完成 flush。
