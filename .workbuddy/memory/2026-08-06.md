## 高考算法模块：全局逻辑删除干扰修复（2026-08-06）

### 根因
后端 `application-dev/prod.yml` 配置了全局 `logic-delete-field: isDeleted`，导致所有有 `isDeleted` 字段的实体（不管有无 `@TableLogic`），MP 内置方法（`selectOne`/`updateById`）都会自动：
- SELECT 追加 `AND is_deleted=false`
- UPDATE 追加 `AND is_deleted=false` 到 WHERE，且从 SET 排除 `is_deleted`

### 修复清单（共 4 后端文件 + 1 前端文件）

**问题1：专业组「删除」不生效**
- 文件：`AdmissionGroupServiceImpl.java` → `delete()` 方法
- 改前：`entity.setIsDeleted(true) + updateById(entity)` → MP 排除 is_deleted SET → 无效
- 改后：`admissionGroupMapper.updateIsDeletedById(id, true)`（自定义 @Update）

**问题2+3+4：专业组列表默认筛选 + 文案**
- 文件：`group/index.vue`
- `isDeleted` 默认 `false` → `undefined`（展示全部），reset 同步
- 按钮 `批量软删除` → `批量禁用`，确认文案同步

**问题5：专业明细 selectByIdCustom 查不到禁用数据**
- 文件：`AdmissionMajorScoreMapper.java` → `selectByIdCustom`
- 改前：`default` 方法用 `selectOne(LambdaQueryWrapper)` → MP 追加 is_deleted=false
- 改后：自定义 `@Select("SELECT * FROM t_admission_major_score WHERE id = #{id}")`
- 同时 `AdmissionMajorScoreServiceImpl.update()` 移除 `|| existing.getIsDeleted()` 判断

**额外修复：AdmissionGroupMapper.findByIdIgnoreLogicDelete**
- 文件：`AdmissionGroupMapper.java`
- 同 selectByIdCustom 问题，改为自定义 `@Select`
- 同时 `AdmissionGroupServiceImpl.update()` 移除 `|| existing.getIsDeleted()` 判断

**问题6：一分一段次修改禁用记录静默失败**
- 文件：`ScoreRankMapper.java` + `ScoreRankServiceImpl.java`
- `ScoreRank` 有 `@TableLogic`，`updateById` 追加 `is_deleted=false` → 禁用记录 0 行更新不报错
- 新增 `updateByIdCustom` 自定义 `@Update` 绕过逻辑删除 WHERE

**问题7：专业组「修改」成功但数据没变**
- 文件：`AdmissionGroupMapper.java` + `AdmissionGroupServiceImpl.java`
- 根因：`update()` 方法中 `updateById(existing)` 与 `@Version` 乐观锁 + 全局逻辑删除叠加，可能返回 0 行但未检查返回值 → 静默成功
- 新增 `updateByIdCustom` 自定义 `@Update`（绕过 @Version 和逻辑删除），Service 层检查返回值，0 行抛 BusinessException

**附带修复：前端 group/index.vue 枚举值修正**
- `requirementTypeOptions`：`['2年','3年','必备','必备','必备']` → `['2选1','3选1','必选1','必选2','必选3']`
- `batchOptions`：`['本科','提前','专科']` → `['本科批','提前批','专科批']`

### 经验
- 判断是否为全局逻辑删除的"排除 SET"问题：看 `updateById` 后 `is_deleted` 是否没变
- 判断是否为全局逻辑删除的"追加 WHERE"问题：看 `selectOne` 是否查不到已删除/禁用记录
- 标准修复：自定义 `@Select`/`@Update` 注解（不受 MP 拦截器影响）

**问题8：专业明细「修改」禁用记录静默失败 + 删除不生效**
- 文件：`AdmissionMajorScoreMapper.java` + `AdmissionMajorScoreServiceImpl.java`
- `update()` 第 133 行 `updateById(existing)` → 禁用记录追加 `WHERE is_deleted=false` → 0 行静默成功
- `delete()` 第 156-157 行 `entity.setIsDeleted(true) + updateById(entity)` → MP 排除 is_deleted SET → 标识写不进去
- 新增 `updateByIdCustom` 自定义 `@Update`（绕过逻辑删除），update() 检查返回值；delete() 改用 `updateIsDeletedById`

**问题9：城市「修改」禁用记录静默失败**
- 文件：`CityMapper.java` + `CityServiceImpl.java`
- `update()` 用 `findByIdIgnoreLogicDelete` 查，但 `updateById` 追加 `WHERE is_deleted=false` → 同问题7
- 新增 `updateByIdCustom` 自定义 `@Update`，Service 检查返回值

**问题10：资源「删除」不生效**
- 文件：`ResourceServiceImpl.java`
- `delete()` 使用 `entity.setIsDeleted(true) + updateById(entity)` → MP 排除 isDeleted SET
- 改用已有的 `updateIsDeletedById(id, true, now)`（该 Mapper 本就已有此自定义方法）

**问题11：修改禁用城市时详情报 404**
- 文件：`CityServiceImpl.java` → `updateDetail()`
- 前端修改城市同时调 `updateCity` + `updateCityDetail`，禁用城市的详情也被禁用 → `findByCityId`（MP 内置方法）查不到 → 404
- 改为当详情不存在/已禁用时 `log.warn + return`（跳过详情更新，不报错）
