## ★ 重要发现（改变了方案）
### 1. fileload 的 VIP 门禁依赖私有 bucket，不能改公共读
- 门禁是**三层**：应用层 `@RequireVip` → 存储层私有 bucket → 取用层后端实时签发预签名 URL（1h 过期）
- **但把 bucket 改公共读会让门禁形同虚设**：objectKey 一旦泄露，拼 `https://haifeng1.oss-cn-beijing.aliyuncs.com/{key}` 即可匿名直连
- 实测：`haifeng1` 匿名访问返回 403 `AccessDenied`（私有读确认）
- → 方案：新建独立公共读 bucket 存公开素材，私有 bucket 完全不动
- **门禁在应用层不在 bucket 层**（这点容易误判）

### 2. C 端头像链路本来就是断的
- DB 注释与后端字段都写「`avatarUrl` = 本地静态资源相对路径 `/static/planners/xx.svg`」
- 但 `haifeng-app/src/main/resources/static/` 下**只有 pdfjs**，无 planners；nginx 也无 `/static/` location
- C 端真正可用的图只有 `apps/user/src/assets/images/avatars/avatar-{1..8}.svg`（vite 打包产物，hash 文件名，**不能存进 DB**）

### 3. `uk_institutions_user` 是单列唯一索引 → 演示数据造不出 4 家机构

## 踩坑记录
### 1. 沙箱内校验 Java 的正确姿势
`javac -proc:none` **不可行**：Lombok 不处理 → `@Data` 生成的 getter 全找不到符号。
正确做法：`-proc:full` + 显式 lombok processor + **输出到临时目录**（绝不碰 `target/classes`）：
```bash
# classpath 用 Windows 路径 + 分号，POSIX 路径 javac 不认
# 全部 jar 会引入旧版本冲突（jjwt 0.11.5 缺 claims(Map) / jsoup 1.10.2 无 Safelist），
# 必须按 pom 声明版本排除旧版
javac -nowarn -encoding UTF-8 -proc:full @/tmp/javac.args -d /tmp/hf-javac-out @/tmp/allsrcs.txt
```
### 2. EP `http-request` 签名
`(options: UploadRequestOptions) => void` 类型不匹配 —— 必须返回 `Promise`（`UploadRequestHandler` 要求
`XMLHttpRequest | Promise<unknown>`），且 `options.file` 才是 `File`。
### 3. `el-form validate` 回调签名
`FormValidateCallback` 返回 `void | Promise<void>`，**不能 `return false`**；
要拿失败字段用 `validate((invalidFields) => { ... })` 回调里取 `Object.keys()`。
### 4. `v-model` 传可选数组的 TS 报错
子组件 prop 声明 `string[]`，父组件字段是 `string[] | undefined` → 用 computed 代理：
```ts
const tagsProxy = computed<string[]>({
  get: () => formData.value.tags ?? [],
  set: (v) => { formData.value.tags = v },
})
```
### 5. `Short` 不能由三元表达式的 `int` 隐式转换
`vo.setStatus(cond ? 0 : 1)` → 编译错误「int 无法转换为 Short」，须写 `(short) 0 : (short) 1`。
### 6. 相对路径 import 层级
`views/home/constants.ts` 从 `views/home/planner/components/` 出发是 `../../constants`（不是 `../constants`）。
