# 2026-08-07 工作日志

## 志愿表"新建"被后端复用旧表导致 400 报错修复（后端 + 前端）
- 现象：user 端 `gaokao/Groups.vue` 勾选专业 → `gaokao/PlansList.vue` 点「新建志愿表」→ 报 `{"code":400,"msg":"以下专业已在志愿表中: [3]"}`；删掉旧志愿表后能成功。用户困惑：VIP 有 10 个志愿表名额却用不上。
- 根因（后端 `haifeng-app/.../wish/WishPlanServiceImpl.addMajors`）：
  - 前端 `PlansList.createPlanAndAddMajors` 首次调 `addMajors({planId: null,...})`，期望后端**新建**一张表并返回 id。
  - 但后端 `getOrCreatePlan` 的旧语义是：`planId==null` 时 `selectOne(memberId 最新一条 LIMIT 1 FOR UPDATE)`，**有表就复用最新那张**（DTO 注释原话"为空时自动获取或创建最近的方案"，旧单表时代设计）。
  - 结果：已有表 A（含专业3）时点新建 → 实际往 A 加 → M3 重复校验（`eq(planId).in(majorIds)`）发现专业3已在 A → 400。**永远建不出第 2 张表**，10 个名额形同虚设。
- 修复：
  - 后端 `WishPlanServiceImpl`：`getOrCreatePlan` 改为 `createPlan(memberId, gaokao, planName)`，**去掉"复用最新表"逻辑，planId 为空总是新建**，仍受 `getMaxPlans`（normal 1/pro 5/vip 10）数量上限检查；同步更新 `addMajors` 调用与注释。
  - 后端 `WishPlanAddMajorsDTO`：注释更正 + 新增可选 `planName` 字段。
  - 前端顺带修复连带 bug：`PlansList.vue` 用户输入的志愿表名 `planName` 之前**从未传给后端**（参数接收后丢弃，后端永远自动命名"我的志愿方案N"）。现在 `addMajors` 带上 `planName`（`api/wish-plan/index.ts` 类型加可选字段），后端 `createPlan` 优先用传入名、空则自动命名。
- 验证：user 端 `vue-tsc --noEmit` 改动文件 0 报错；后端未跑 mvn（JVM 在跑，红线），静态 grep 确认无 `getOrCreatePlan` 残留引用。
- **注意：后端改动需重启后端才生效**；建议实测：已有 1 张表含专业X → 再勾 X+新专业 新建表 → 应成功创建第 2 张表且自定义名称生效。
- 经验：跨表唯一性校验（"专业已在志愿表中"按 memberId+planId 查）一旦遇到"新建"流程必须先确认后端 planId 为空时的语义是"新建"还是"复用"，否则会误报重复。

## 志愿表详情页安全等级球修复（用户确认后端补字段，2026-08-07）
- 承接上一条：`PlanDetail.vue` 的「安全等级球」显示 `group.levelShort`（搏/冲/稳/保/垫色块）和 `group.safetyLevel*100%`，但后端 `WishPlanGroupVO` 没这两个字段。
- 数据来源：`AdmissionGroupPageVO`（专业组列表）的组级安全等级 = `safetyLevelService.calculateMajorSafety` 对组内所有专业取 **max**（`AdmissionQueryServiceImpl.buildGroupVO`，无专业时默认 0/"禁"）。志愿表快照 `WishMajorSnapshot` 实体已存每个专业的 `safetyLevel`/`levelShort`（添加志愿时已算好）。
- 后端改动：
  - `WishPlanGroupVO` 加 `BigDecimal safetyLevel` + `String levelShort`。
  - `WishPlanServiceImpl.toGroupVO(snap, groupMajors)` 新增参数：遍历组内专业快照取 max(safetyLevel) 跟随 levelShort（与 buildGroupVO 算法一致，空列表默认 0/"禁"）；`pageGroups` 已批量查好 `majorsByGroup`，改传参即可（无 N+1）。
- 前端改动：`api/wish-plan/index.ts` 的 `WishPlanGroupVO` 类型加 `safetyLevel?: number`、`levelShort?: string`；`PlanDetail.vue` 模板两处加兜底（`group.levelShort ?? ''`、`(group.safetyLevel ?? 0)`），旧后端未重启也不崩（显示灰色/"0%"）。
- 验证：user 端 `vue-tsc --noEmit` **0 错误**（此前 3 个 TS2339 消除）。
- **注意：后端改动需重启才生效**，重启后志愿表详情页等级球应显示正确颜色与百分比。
- 经验：给 VO 补展示字段时，优先复用已存快照数据（WishMajorSnapshot 已有专业级 safety），组级=max(子级)，避免重算；前端类型用可选 + 模板兜底可兼容"旧后端未重启"过渡期。
